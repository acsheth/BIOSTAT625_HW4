### 4. Comparison of correctness and efficiency

The vignette calls `all.equal()` on coefficients, deviance, and fitted values against `stats::glm(..., family = binomial())`, on both `icu_sim` and a simulated sample of 4,000 rows. It also fits a grouped binomial model (`cbind(success, failure)`).

`compare_with_glm()` collects those checks for the R engine and the C++ engine. With `n_bench > 0` it times `glm`, `logit_fit(engine = "r")`, and `logit_fit(engine = "rcpp")` with `bench::mark()`. The vignette prints that timing. The implementation is not required to beat `glm`.

The R code is split by job:

## Optional grading criteria

### 1. Rcpp

`src/logit_irls.cpp` runs the same Fisher-scoring iteration in C++. Each iteration accumulates `X'WX` and `X'Wz`, scales the columns, and solves the system with a Cholesky factor. `compare_with_glm()` and the vignette time this engine against the pure R engine. If the cross-product matrix is numerically singular, the fit is repeated with the R QR engine and a warning is issued. Rank-deficient model matrices are sent to the R engine immediately so aliased coefficients are `NA`, matching `glm`.

Building the package requires a C++ toolchain (Rtools on Windows).

### 2. testthat

`tests/testthat/` covers the fit, the S3 methods, input validation, convergence warnings, separation, and `compare_with_glm()`. `tests/testthat.R` is the standard `test_check("logitfit")` runner. `DESCRIPTION` sets `Config/testthat/edition: 3`.

### 3. Continuous integration

`.github/workflows/R-CMD-check.yaml` runs `R CMD check` on Ubuntu, Windows, and macOS with the current R release, using `r-lib/actions`. Tests run as part of that check. The first green run happens after the repository is pushed to GitHub.

### 4. Code coverage

`.github/workflows/test-coverage.yaml` runs `covr::package_coverage()` and fails the job if coverage is below 90%. It writes a Cobertura file and uploads it to Codecov when `CODECOV_TOKEN` is set. `codecov.yml` records the same 90% target.
